# 2026-10-24 代码与设计文档复核

基线：`1899618`，`@tensorix/metahub` 0.5.4。开始时工作区干净。本次交付只修改 docs；确认的业务缺陷保留为待修复项，没有把修复建议写成已落地能力。

## 已确认的问题

### P1 · CSV 导入可更新目标数据库以外的记录

位置：[files.ts](../../src/core/sync/files.ts) `importDb`（`rowId` 分支）。CSV 的 id 列先调用全局 `getRecord(db, rowId)`，找到即调用 `updateRecord(db, rowId, data)`，没有检查其 `database_id` 是否等于导入目标。

复现：建 A、B 两库，都有 text 属性 Title；B 新建值为 `original B` 的记录 r。向 A 导入 `id,Title\n<r.id>,unexpected edit`。隔离内存库的实际结果是 **A 仍 0 行、B 的 Title 变成 unexpected edit**。这是跨目标写入，不是按 A 库 upsert。

建议：在任何写入前校验全部显式 id 的归属，跨库时报 `invalid_input`；另明确文件级事务策略，避免后续某行失败而前面已提交。回归需同时覆盖本库 id、跨库 id、未知 id、空 id，以及非法行前已有合法行。

### P1 · 重名属性 CSV 导出有损

位置：[files.ts](../../src/core/sync/files.ts) `exportDb`（`props.map` 分支）。普通属性通过 `r.values[p.name]` 取值，而重名属性的 `values` 本来就是有损映射。

复现：同库两列都叫 Title，按 property id 分别写 `first`、`second`；导出得到 `id,Title,Title` 与 `<id>,second,second`，第一列的值丢失。relation/doc 分支用 `cells[p.id]`，没有修复普通属性分支的问题；重复表头本身也无法唯一导回。

建议：读取一律按 `cells[p.id]`；表头需提供无歧义编码或在重名时明确拒绝导出，导入端使用同一规则。不要只改取值却继续宣称重复名称可无损往返。

### P2 · 数据库复制没有重映射保存视图的属性引用

位置：[databases.ts](../../src/core/databases.ts) `duplicateDatabase`（复制 meta 与建立 propIdMap 的两段逻辑）。先原样复制除 collapsed 外的 meta，再为属性生成新 ID。记录单元格已走 `propIdMap`，`meta.views` 没有。

复现：源库保存 `sort:[{prop:源属性ID,desc:false}]` 与 `hidden:[源属性ID]`，复制后新库属性 ID 已变化，但 views 中仍是源 ID。`view-model.ts applyFilter/applySort` 忽略找不到的属性，因此对应规则失效；隐藏列、分组、日期列、计算配置也需要统一处理。

建议：定义视图引用迁移器，用属性映射重写 sort/filter/hidden/group/dateProp/start/end/calc；如自关联筛选值引用源记录，也需记录映射。保留未知 meta key 的领域中立性，不对任意字符串盲目替换。

### P2 · 当前测试门禁失败：英文翻译存在未使用条目

位置：[i18n.test.ts](../../src/webui/i18n/i18n.test.ts) 第 47 行及 `src/webui/i18n/en/*`。完整 `bun test` 在 unused-key 断言失败，示例有「创建另一条链接」「固定快照」「当前链接」等旧分享界面文案。missing-key 检查通过，本次失败不是缺翻译。

建议：按当前调用点删除废弃条目，保留确有使用的文案，不通过放宽断言隐藏漂移。
