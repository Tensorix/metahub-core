# 移动端资料库验收 · 2026-11-05

iOS 使用 SwiftUI List 的数据驱动 ForEach。Android 使用 FlatList。两端的树查询均从工作区本地副本读取，行的身份使用文档 ID，根与各父节点独立续载。下拉会重新读取本地结果、尝试同步，并刷新当前范围。搜索使用独立列表，清空搜索时回到原树。

| 环境 | 实测结果 |
|---|---|
| Bun、SQLite，10,000 篇合成文档 | 初始化执行 1 次查询，向 UI 返回 60 个根项。SQL 最多读取 61 条摘要，用多出的 1 条判断能否续载。遍历根分支得到 9,599 个不同 ID；展开 400 个直接子项和孙项，核对深度、顺序、搜索路径、移动后归属及孤立文档。 |
| iOS 27 Release，10,000 篇合成文档 | 原生手势展开首个父项，向上滚动穿过该分支第 60 个子项，自动出现下一批。相同列表另做挂载探针测试，首屏观测到 11 个已挂载数据行，展开后连续滚动观测峰值为 44。探针统计 React 数据行，并非整个应用原生视图数量。 |
| Android Release，Pixel 9 Pro 模拟器 | 展开父项，滚动跨过 60 个子项，验证下一批仍属于原分支。在不可达的同步端点下，两端执行实际下拉手势后均显示同步失败提示，已有行仍能展开和浏览。 |
| 真实工作区，iOS Preview | 只读查询本地副本，核对首个被测父项展开后可见的 10 个子项及顺序。点子项进入编辑器，返回资料库后父项仍展开。 |
| 无障碍 | iOS 可访问性树能分别定位标题按钮和带文档名的展开、折叠按钮。实际 VoiceOver 朗读列为独立真机验收项。[Apple 测试说明](https://developer.apple.com/documentation/accessibility/performing-accessibility-testing-for-your-app) |

共享回归命令为 `bun test apps/mobile/src`，222 项通过。移动端 TypeScript 及变更页面、列表组件和查询模块的 ESLint 检查通过。合成工作区和测试探针均独立于日常预览包。
