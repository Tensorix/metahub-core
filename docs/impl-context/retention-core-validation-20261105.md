普通文本的共同基线恢复已实现；结构编辑、缺基线与其他实体仍采用保全副本。文档历史已按约 1 MiB 目标分块，每块携带必要的块归属记录，可独立验证并按需下载。单个不可分割字段及当前状态对象仍有 64 MiB 解码硬上限；超大单字段会安全拒绝发布。HTTP 对等编辑仍需来源设备把操作提交到桶，不能用 HTTP 游标替代来源连续序号证明。

## 桌面和 PWA 原地重建

桌面和 PWA 都在「设置 → 数据与备份 → 本地副本与恢复」提供「保全编辑并重建本地副本」。首次连接已有 v2 检查点的独立 PWA 也会在进入工作区前显示该入口。完成后可以逐项创建恢复副本或丢弃编辑。历史按文档按需读取，已下载的修订可以离线打开。

桌面会冻结工作区窗口，等待编辑器确认保存，再暂停 Bun sidecar。保护目录位于工作区的 `recovery/<事项 ID>/`，含一致性 SQLite 备份、校验清单和本地附件。重建在独立进程中进行。只有 shadow 数据库校验通过，才在原库事务中发布新库指针。已持有旧连接的写入者必须重新打开数据库。失败时，Electron 在同一地址重新启动原服务。

PWA 由持有 OPFS 的 worker 执行交换。保护数据库包含 SQLite 副本和从 IndexedDB 读回校验的待上传附件。切换前需要当前标签页独占副本，其他已打开的工作区标签页会阻止开始重建。保护文件和未处理的恢复事项保留在本地。

两端均使用临时配置和本地合成桶。桌面和 PWA 的验收脚本分别为 `scripts/rebuild-desktop-acceptance.ts` 和 `scripts/rebuild-browser-acceptance.ts`。运行桌面脚本前构建 Electron main 和 preload，并通过 `MH_ELECTRON` 指定 Electron 可执行文件。浏览器脚本支持通过 `MH_PLAYWRIGHT_MODULE` 和 `MH_CHROME` 指定本机测试运行时。本机 VPN 将 IPv4 回环地址路由到隧道，因此端到端验收使用本机 IPv6 回环，完整共享回归使用无外部网络的临时容器。
