# iOS 文档首字延迟，2026-11-05

## 验收口径

从首页文档行的 `onPress` 开始计时，到真实模拟器键盘输入的数字首次改变正文为止。CodeMirror 在正文变更事务中取时间，Lexical 在可编辑正文获得焦点后，通过文本变更监听器取时间。DOM 端记录事件发生的时间，再传回原生端。加载动画消失、编辑器 ready、键盘弹出和自动保存分别观测。

对照使用本地同一份 `THINK` 的标题和 501 字符 Markdown。正文不进入报告和测试仓库。使用 Xcode 27.2、同一台 iOS 27.0 模拟器和 Release 包。每轮终止并重启应用，启动后等待 6 秒，从首页点开文档。工具在编辑器报告就绪后点击第一段并通过 HID 输入数字，直到正文接受输入。每组 4 轮，轮换测试顺序。

计时包使用实际项目的编辑器和 Expo 导航。对照组从本地固定数据读取内容，排除账号、远程服务和网络时延。Lexical 使用另一个项目的文档页、Expo DOM 组件和 iOS 原生工具栏。该项目使用手动保存。

## 对照结果

单位为毫秒，各阶段分别取中位数。

| iOS 路径 | 点击到取得数据 | 取得数据到编辑器就绪 | 就绪到首字 | 点击到首字 | 四轮首字原始值 |
|---|---:|---:|---:|---:|---|
| 优化前的单 CodeMirror | 14 | 2111 | 486 | 2611 | 2913、2514、2675、2547 |
| 另一 Expo 项目的 Lexical | 36.5 | 2263 | 419.5 | 2746 | 2876、2826、2593、2666 |
| 优化后，首页已预热 | 11 | 132.5 | 438 | 573.5 | 695、574、573、536 |
| 相同新实现，关闭预热 | 14.5 | 2050.5 | 519.5 | 2581.5 | 2733、2512、2563、2600 |

优化前后，首字到本地自动保存的中位数分别为 652、654 毫秒。表中就绪到首字包含点按、键盘及测试工具的事件投递时间。样本反映这台模拟器和这份文档，未测真机尾延迟。

## 完整 dev 路径复核

单独使用完整的 dev 首页、文档路由、SQLite 副本、保存队列与 iOS 原生模块，通过测试探针取时间。每轮还原相同的隔离工作区，从首页“最近打开的文档”点击 THINK，正文接收首字耗时分别为 668、566、748、587 毫秒，中位数 **627.5 毫秒**。首字到本地保存中位数 **659.5 毫秒**。重新读取数据库确认实际写入了测试数字；第二篇文档的内容独立。日常预览设备安装了无探针的 Release 包，并打开 THINK 复核。

## 实现与边界

首页所在的标签导航获得焦点时，iOS 在空闲时间加载一次不含任何文档数据的本地 WebKit 页面。点开任意文档后，页面才接收当前会话的正文、版本和草稿，并启动一个 CodeMirror 实例。已交给文档的页面不会重新放回池中。后台或内存警告会释放尚未使用的页面。编辑、附件和版本检查继续使用现有原生桥和保存队列。首字中位数下降约 78%，主要收益来自把 WebKit 启动移出文档打开路径。

冷启动直接打开文档、预热未完成或预热页被回收时，需要现场启动 WebKit。关闭预热的对照组给出了这条路径的参考时间。

## Lexical 对照包说明

原项目使用 Expo SDK 56 预览版。为在本机 Xcode 与 iOS 27 上运行，在临时副本中适配了 Scene 启动入口、Swift 函数指针编译和模拟器部署目标。还修复了临时 SDK 的初始属性转义：原实现把 JSON 插入反引号字符串，THINK 中的两个 Markdown 反引号会使 WebView 的初始化脚本出错。修正后使用原文和正常的外部打包脚本测速。上述适配均未写回另一项目。
