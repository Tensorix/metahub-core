# iOS 编辑器会话复用验收 · 2026-11-05

## 生命周期

工作区持有一个已加载本地 HTML 的 WKWebView。文档路由得到焦点后，先读取当前 SQLite 副本或已落盘的草稿，再用新的会话 ID 创建 CodeMirror。关闭时原生冻结输入，等待组合输入、草稿写入和版本保存。网页回传选区和滚动位置，销毁编辑器，清除请求、监听器、定时器和文档引用，原生才将视图交还工作区。普通返回和打开链接都使用这条路径。进入附件选择器、取消侧滑和打开版本面板保留当前会话。

导航栈保留文档 ID、版本、选区和滚动位置。返回时重新读取数据，选区限制在新正文的范围内。每次创建新的撤销栈。工作区实例变化会淘汰旧运行时，空闲运行时可以被系统回收。保存成功但关闭应答丢失会丢弃原视图，再为目标文档建立新运行时。仍在输入或保存失败时留在原文档。

这套实现取代了之前在编辑器就绪后准备下一张空白页的实验。新版 JS 按原生协议能力选择复用路径。Android 和旧 iOS 二进制继续走原有 WebView 宿主。

## Release 测量方法

使用 iOS 27.0 的隔离模拟器、Release 构建、真实文档路由和本地 SQLite。A 来自同一份 501 字符的 THINK，B 是隔离工作区中的第二篇文档。每轮重启应用并还原同一份测试库。首次打开前首页空闲 6 秒。返回重进时点击可用的首页文档行。打开 B 通过测试入口调用实际文档链接处理器，返回 A 使用系统导航栏按钮。每个目标都通过模拟器键盘向正文输入数字，以 CodeMirror 收到实际变更时的时间为终点。首字统计含导航转场、聚焦与键盘投递。每组十轮，P90 取排序后的第九项。

HTML 加载和会话标识通过隔离包的原生探针记录。系统文件选择器、真实拼音组合输入与 WebKit 进程终止在该模拟器上测试。磁盘满、保存延迟、并发远端写入及关闭应答丢失通过故障注入触发。日常预览包使用同一生产代码，移除了测试入口和探针。测试输入仅写入隔离工作区的副本。

连续打开、关闭同一文档 20 次，原生记录了 **1 个运行时 ID、1 次 HTML 加载、20 个不同会话 ID、20 次关闭确认**。A → B → A 的三次打开也共享同一个原生运行时。打包后的网页会话测试逐次检查活动 CodeMirror 数量，打开时为 1，关闭后为 0；空闲监听器计数没有增长。

空闲时注入系统内存警告，下一次打开 THINK 新建了运行时。该次点击到 ready 为 1792 毫秒，到真实首字为 **2152 毫秒**（单次观测）。

完全冷启动单独测量。每轮终止应用、还原数据库，禁用首页预热。首页可点后立即打开 THINK。点击到首字的中位数为 **2541.5 毫秒**，P90 为 **2703 毫秒**。十轮为 2683、2703、2731、2660、2535、2507、2548、2509、2519、2518 毫秒。

## 数据安全验证

| 场景 | 检查 |
|---|---|
| 本地写入失败、远端同块冲突 | 返回被阻止，原文档仍持有输入，SQLite 草稿保留。解除写入故障后可重试。冲突时远端版本和本地草稿各自可读。 |
| 保存时打开 B | 注入 800 毫秒保存延迟，B 等待 A 保存后才接管。连续两个目标请求另用会话协调器测试，最后仍有效的请求获准进入。 |
| 中文输入中返回 | 系统拼音正在组合时尝试返回，尚未确认的输入使 A 保持活动，解除冻结后选定候选字再返回，通过正文差异确认新增汉字写入了 A。 |
| 原地重建 | 在 A 输入后触发实际重建，使用隔离的合成对象存储。核对新数据库和保护副本均包含最后的按键，重建后运行时标识改变。 |
| 系统文件面板取消、短距离边缘侧滑取消 | A 保持原会话，取消后继续输入，正文保存到 A。 |
| 整个应用进程在保存前退出 | 看到 SQLite 中的最后一个按键和待保存草稿后终止应用。重启、重新打开 A，确认正文含该按键，已确认草稿才会清除。 |
| WebKit 在草稿落盘后终止 | 通过恢复入口重新打开，SQLite 正文含终止前的最后一个测试数字。 |
| 保存后关闭应答丢失 | 原生丢弃旧视图，下一次打开获得新的运行时 ID。 |
| 网页会话隔离 | 已销毁的桥拒绝未完成请求。A 的回包与 B 的请求即使同为 1 号也无法串用。检查监听器数量、每次重开的 CodeMirror 数量、撤销隔离、远端刷新及正文缩短后的选区。 |

共享保存、编辑器、移动端库和 core 文档测试使用 `bun test apps/mobile/src src/core/documents.test.ts src/webui/document-save.test.ts`，262 项通过。移动端 TypeScript 与本次修改涉及的移动端 ESLint 检查通过。
