# 移动端数据表打开性能验证

状态：2026-11-11 已完成本轮实现、必要回归与正常 iOS Release 安装。按用户最新要求简化性能验证，停止完整压力矩阵；以下结果不代表原计划全部性能指标已验收。

## 实现范围

- 独立 iOS `MetahubDatabase` 模块：固定离线 HTML、一个活跃实例与一个闲置上限、会话清理确认后回收；后台与内存警告释放闲置实例。文档原生模块保持独立。
- 元数据与运行壳并行准备，原生标题复用元数据；按深链接/设备偏好提前准备查询及表格第一页，Web 接管时校验查询版本。
- 查询协议 v2：手动排序使用现有 SQLite 索引及稳定游标；无排序筛选渐进发布结果与统计；复杂排序只投影相关字段，使用可取消扫描/排序。旧接口继续可用。
- 普通记录缓存上限 1,000；草稿批量查询，读普通记录不创建写入器；相关数据库变化才使移动端查询失效。
- flush 合并重复请求，仅等待写入；既有写入错误不会因 promise 已结束而消失；视图与滚动位置的防抖写入在退出前提交。
- 独占会话、嵌套返回的新会话标识、已确认草稿与偏好恢复；关闭超时的原生运行实例销毁。
- Android 保留 `react-native-webview`，共用数据和会话接口。

预热策略采用保守实现：每次首页空闲只预热最近使用的类型。现有文档模块的 warm API 不返回“壳已就绪”状态，所以不串接第二次预热，以免两个 WebKit 初始化实际重叠。未修改文档原生模块来扩展该 API。

## 计时口径与测试夹具

- 设备：Metahub Preview，iOS 27.0 模拟器，UUID `89211314-4AB1-4E35-8A34-28A8A238AF96`。
- Release 构建；独立 `database-opening-benchmark-v1.db`，不加载真实凭证、不启动同步、不改用户记录。
- 16、10,000、50,000 行，每条 50 列；普通手动排序，以及数值字段 `ge 3` 筛选、降序排序。
- 每个组合分别 20 次杀进程冷开和首页返回后的热开。采样脚本为 `apps/mobile/scripts/benchmark-database-opening.ts`。
- 当前原生指标是 **数据表路由挂载 → Web 首屏数据提交消息到达原生**。不是首页点击到可交互，也不包含启动整个应用的时间；`onLoadEnd` 不作为完成标志。
- 原生与 Web 分别使用自身单调时钟，禁止跨环境相减。
- 兼容基线使用保存的旧数据表 HTML 与普通 RN WebView；隔离夹具运行在本轮原生宿主上。因此它是共享环境下的兼容基线，不能冒充整个历史版本二进制。另保留了改动前真实小表的独立日志与应用包。
- 复杂筛选夹具最初误写为 `gte`，发现后已改成实际支持的 `ge`，对应无效复杂查询样本已剔除并重新采集。

## 自动化验证

最终工作区回归：两批共 91 项通过，0 失败（13 个文件 63 项、4 个文件 28 项）。覆盖查询/分页/统计、HTTP/Worker/ReplicaService、四视图在同一离线壳中换表重开、草稿、旧会话消息、失败写入、粘贴、虚拟化及实例所有权。

最终移动端 TypeScript、Web TypeScript、移动端 lint、Web 完整构建、离线数据表包构建全部通过。离线壳 1,173 KB。iOS 与 Android Release 均构建成功。

## 简化实测结果

单位 ms；每格为中位数 / P95。下表各组前后均 20 次，应用错误 0 次。仅对比同一模拟器路由挂载到首屏提交。

| 数据与查询 | 打开方式 | 兼容基线 | 优化后 |
|---|---|---:|---:|
| 16 行 × 50 列，默认 | 冷开 | 978 / 2071 | 830 / 908 |
| 16 行 × 50 列，默认 | 热开 | 660 / 1196 | 280 / 321 |
| 1 万行 × 50 列，默认 | 冷开 | 2149 / 2334 | 802 / 912 |
| 1 万行 × 50 列，默认 | 热开 | 1872 / 2210 | 249 / 286 |
| 1 万行 × 50 列，复杂筛选排序 | 冷开 | 2542 / 2612 | 1679 / 1693 |

复杂排序热开只采了 5 次，中位数约 1680 ms，不用这 5 次宣称 P95 达标。它仍需计算完整有序结果，尚未达到原计划复杂查询 1 秒目标。普通表格的首屏路径已不随整表扫描增长；本轮没有完成优化后 5 万行模拟器矩阵，不推断其结果。

原始数据与逐阶段汇总见 [evidence](database-opening-evidence/simulator-summary.json)、[baseline](database-opening-evidence/baseline-simulator.json)、[optimized](database-opening-evidence/optimized-simulator.json)。基线另有一次测试 HTML 注入错误，已标记 fixtureError 并重跑，不计入应用错误或有效样本。

运行实例日志在采样时持续记录 created=1、active=1、idle=0，支持同进程热开复用；不能替代完整内存泄漏测试。

## 不可据此宣称通过的指标

- 点击到可交互的 P95 目标、主线程长任务、真机滚动 FPS、输入延迟与内存峰值。
- VoiceOver/TalkBack、真实中文输入法及真机后台恢复。
- 全量编辑、故障恢复、中文输入、无障碍矩阵未在最终安装版逐项跑完；自动化测试不能替代这些真机行为验证。

基线校正补充：旧壳的深链接只识别布局名称，不识别保存视图 ID。复杂查询组因此不能只传 `view=v_complex`；已给旧测试 HTML 注入对应的设备视图偏好（使用其原有选择机制），剔除先前落在普通表格上的复杂组样本后重新采集。普通查询样本保留。此夹具修正不改渲染或查询实现。
