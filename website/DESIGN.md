# Website design

A product introduction for a local-first shared workspace: notes, typed tables, and agent-built sites. Humans and external agents read and write the same materials. Mode: Persuade. Preserve the multicolor MetaHub mark; distinguish brand artwork from interface colors.

- Interface palette follows `LIGHT_THEME`: warm canvas #fafaf9, white paper, foreground #37352f, secondary text #6f6d66, borders #eae9e6, quiet surfaces #f1f1ef. Primary actions, focus and selection use #3867b2 and #edf2f9.
- Brand artwork retains the logo's saturated blue/violet/teal/coral. Hero emphasis uses #335cff; decorative scene icons, the active workflow node ring, and the site mark use original logo violet #8b6cef, teal #16b8ad and coral #f48265 for energy. Labels remain readable with the app's subdued purple #79619d, teal #397d76 and orange #a06436 on pale tints. Color accompanies text, numbering and selection cues. Success and warning colors keep their semantic meanings. The terminal follows the app's dark neutral palette.
- Type: self-hosted Manrope (regular and bold), system CJK fallback; monospace only for commands and paths.
- Chinese typography: full-width glyphs use normal tracking and more leading. The hero breaks after “你和 AI”, keeps “接着往下做” blue and intact, and scales the complete second line to phone widths. Supporting copy uses balanced or natural wrapping; app examples keep their compact document/table hierarchy.
- Locked hero: “Where you and your AI keep working.” / “你和 AI 接着往下做的地方。” Badges: Write · See · Continue. CTAs: Download desktop / Connect an agent.
- Content width: 1200px (1240px on wide screens). Centered compact hero followed by one fixed-height demonstration area with Notes / Tables / Sites tabs. The three demos stay in the same place and retain independent interaction state.
- App fidelity: colors from `src/core/ui-theme.ts`; font stack, 6/8px radii, sidebar tabs, document spacing, data grid, and main-app board patterns from `src/webui/styles.css`. The sample hosted site uses the app's subdued brand teal; the write-back table keeps the app's neutral palette. Agent narration and playback controls remain outside the app frame.
- Sequence: you write → AI writes back → you revise → AI explicitly re-reads. Each scene offers one automatic walkthrough and manual, repeatable interactions. Notes update only after re-reading; board summaries reflect a read snapshot; a site sign-up writes to the displayed attendee table.
- Motion: 350ms scene transition; 520ms card movement between columns; bounded read indicator, paragraph reveal, and row insertion. User changes, scene/language switches, hidden tabs, and offscreen demos cancel pending work. Reduced motion skips autoplay and spatial effects but keeps textual feedback.
- Responsive: 1100px, 900px, 700px, and 440px. Sidebar recedes on mobile; cards scroll inside their board. On phones, the site and its write-back table switch in place, with successful sign-up revealing the table. No vertical scene stack.
- Localization: English default, persisted English/Chinese switch. All visible and assistive labels live in `public/copy.js`; task IDs, dates, and sample identities remain language-independent. User-entered names are preserved literally. Metadata updates with language. Source app screenshots remain explicitly versioned English evidence.
- App controls: board cards omit the grouping property and show compact typed-property rows, matching `board.tsx`. Status cells and column headings use `cells.tsx` option chips. Table status editing uses the app's searchable popover pattern (bottom sheet on phones); board dragging remains available. Date selection, board guidance, the written-back summary and the site write-back caption sit outside the app viewport as demo annotations. The document itself shows plain date text and ordinary prose rather than bespoke inputs or AI cards. The demonstrations show a compact subset of WebUI; they do not implement a complete editor, schema manager or navigation tree.
- Accessibility: semantic tabs with arrow/Home/End navigation, visible focus, keyboard-searchable status choices as an alternative to card dragging, Escape dismissal and focus return, status announcements for manual operations, and reset/pause controls.
- Supporting content: expandable real app screenshots, local ownership and sync, harness-specific agent setup, and desktop/CLI installation. The connection section offers Codex / Claude Code / Other agents tabs: supported harnesses show the actual `mh init --codex` or `mh init --claude` command, a copy action, and the subsequent `$mh` or `/mh` invocation. Other agents receive a copyable prompt to fetch and install the skill from its raw URL, set up the CLI if needed, and read existing workspace material. The user pastes it into their AI conversation; do not send them to read a technical guide or invent unsupported init flags. This section teaches setup, not low-level document CRUD. All claims are grounded in the repository. Demonstrations are explicitly simulated and use page-local data only.

The Other agents prompt is collapsed by default. “Copy for your AI” always copies the complete prompt; “Show details” reveals the prerequisites and prompt inline. Clipboard failure opens the details for manual copying. Both labels and feedback are localized.
